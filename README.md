# Jikanwari（時間割PWA）

大学の時間割作成・シラバス検索・卒業要件確認をオフラインでも行えるPWA。旭川大学経済学部経営経済学科を想定した実装。

## 主な機能

- **時間割**: 学年（1〜4年）× 学期（前期/後期/集中）× 曜日・時限の時間割。入学年度から「今何年生か」を自動判定し、現在の学年・学期を初期表示する（4月始まりの学事年度基準・セレクトで自由に切替可）。外国語科目のように週2コマある科目（英語Ⅰ①②等）は `Course.meetings` として全コマを保持し、追加・自動配置時は2コマとも配置、削除時は2コマとも削除される。セルをタップすると、割当済み科目の詳細（教員・単位・評価方法・シラバス・卒業要件区分）や、その時間帯に開講している他の科目の候補一覧（履修登録ウィザード）が表示され、ワンタップで追加・削除できる。
- **初回セットアップ**: 初回起動時に入学年度と所属コースを確認するダイアログを表示。在学期間に対応する年度（入学年度〜+3年）のシラバスを自動で読み込み、必修科目（クラス分けのある科目は1クラスのみ）を全学年の時間割へ自動配置する。
- **必修はデフォルトで自動配置**: 設定画面で入学年度・学部・学科を保存すると、対応する履修ガイドの必修科目が全学年・全学期の空きコマへ自動的に配置される（学生が選ぶ必要はない）。手動でも時間割/履修プランナーの「必修を自動配置」から再実行できる。
- **選択必修は選ぶダイアログで選択**: 必修の自動配置に続けて「選択必修を選ぶ」ダイアログが開き、選択必修A〜Eの区分ごとに候補科目とチェックボックス・必要単位に対する選択済み単位数が表示される。選択すると履修予定(planned)として記録される（設定画面や履修プランナーからいつでも選び直せる）。
- **履修プランナー**: LLM（AI）は使わず、卒業要件の不足区分・科目データ・時間割の空きコマからルールベースで履修候補を提案。区分（必修/選択必修A〜E/選択/自由選択）ごとに未履修候補を一覧表示し、ワンタップで時間割に追加できる。
- **シラバス検索**: 科目名・教員名・概要・到達目標・評価方法・教科書・キーワードから部分一致・あいまい検索（全角半角統一、カタカナ→ひらがな変換、部分列マッチによるフォールバック対応）。ローカル（IndexedDB）にキャッシュ済みの科目はそこから即座に返し、未キャッシュの検索語のみ `/api/syllabus/search` がサーバー側でスクレイピングを試みる（失敗時は「見つかりませんでした」と表示し、フェイクデータは表示しない）。
- **卒業判定**: 入学年度別（経済学部経営経済学科 2023〜2026年度入学）の卒業要件に対応。設定画面で入学年度・学部・学科を選ぶと、対応する履修ガイド（卒業要件セット）がその場でプレビュー表示され、保存すると自動的に切り替わる。必修・選択必修A〜E・選択・自由選択の各区分の取得単位・不足単位・総取得単位を集計し、円グラフ（達成率）・卒業可否・アドバイス（不足区分の候補科目、評価方法の偏りなど）を表示。各科目がどの区分としてカウントされるかは科目名から自動判定（`classifyCourse()`）され、手動指定でも上書きできる。
- **基幹科目／総合科目の区別**: 「基幹科目群特論／〇〇」「総合科目群特論／〇〇」のように科目名に明示されている科目は `subjectGroup` として区別し、科目カードにバッジ表示、シラバス検索で絞り込みできる（必修/選択必修等の履修区分とは別軸の分類のため、卒業要件の単位計算には影響しない）。
- **履修状況管理**: 履修済み/履修中/履修予定の3状態管理。履修中の科目も卒業要件の進捗に反映される。
- **PWA**: `manifest.json` + Service Worker（`public/sw.js`）でホーム画面追加・オフライン閲覧に対応。
- **レスポンシブUI**: モバイルは下部タブバー、タブレット/PCは左サイドナビに切り替わる。
- **ローカル保存**: IndexedDB (`src/lib/db.ts`) に `courses` / `timetable` / `graduation`（履修状況） / `favorites` / `settings` を保存。サーバーには送信しない。
- **サーバー側共有キャッシュ**: シラバスのライブスクレイピングに初めて成功した検索語の結果は、Next.jsのData Cache (`unstable_cache`) により外部DB・環境変数なしでサーバー側に30日間共有キャッシュされる。以降は同じ検索語について他の利用者がアクセスしても大学サイトへ再アクセスしない。
- **実データ搭載**: `public/data/asahikawa-courses-2026.json`（2026年度・経済学部経営経済学科130科目、実際のシラバスサイトから取得された科目名・教員・曜日時限・評価方法・概要・到達目標・シラバスURL等）を初回起動時に取得しIndexedDBへ格納する。フェイク／デモデータは一切使用しない。取得に失敗した場合は設定画面にその旨を表示し、次回起動時に再取得を試みる（`src/lib/real-course-import.ts`）。
- **全件同期（学年×曜日ベーススクレイピング）**: 設定画面の「大学サイトから最新のシラバスを取得する」から `/api/syllabus/sync` を呼び出し、学年（1〜4年）×曜日ごとに検索を行って科目データを再取得・反映できる（`scrapeAllEconomicsCourses()`）。
- **スクレイピングモジュール** (`src/lib/scraping/`): Campus-Xs（`slbssrch.do`）の検索・詳細ページと、学生生活ページ（`student-guide`）の履修ガイド等のリンクを取得するサーバー専用モジュール。Struts系の `value(...)` パラメータ名の候補を多数保持し、`<select>` の表示テキスト（例:「経営経済学科」）からも所属を絞り込める。`GET /api/asahikawa-scrape?type=syllabus|syllabus-detail|student-guide` から直接呼び出すこともでき、結果はNext.jsのData Cacheでサーバー側共有キャッシュされる。

## 開発

```bash
npm install
npm run dev
```

`npm run build` でVercelへそのまま `git push` デプロイ可能（環境変数不要）。

## 既知の制限・要調整事項

- **卒業要件データ**（`src/lib/graduation-requirements.ts`）は履修ガイド（2024年度P.20-22・2026年度P.9, P.24-25）記載の入学年度別（2023〜2025年度=旧カリキュラム／2026年度以降=新カリキュラム）×コース別（経済学／経営(・法学)／会計(・商学)）の必修・選択必修A〜E科目名リストで判定する。シラバス上の科目名に担当教員名（「ゼミナールⅡ（田中）」）やクラス組（「経済学Ⅰａ」）が付いていても、`courseNameMatchCandidates()` がそれらを外した候補名でも突き合わせるため、履修ガイドの科目名と正しく対応づく。
- **科目データのクリーニング**: `public/data/asahikawa-courses-*.json`（2023〜2026年度・計498科目）には、スクレイピング時に混入したHTMLタグ（`<div class="...">` 等）・HTMLコメント・インラインJS断片（`jq$(function(){...})`。本文はJS内の `var subjectCon = "..."` から復元）・CSSルールが含まれていたため、`scripts/clean-course-data.mjs` で全フィールドから除去済み（科目名に付いていた `<div class="` の断片もこれで解消）。取り込み時（`real-course-import.ts`）と詳細ページ解析時（`asahikawa-scraper.ts` の `<script>`/`<style>` ノード除去＋タグ除去）にも同等のサニタイズを行うため、今後の再取得データにも混入しない。
- **配当学年の補完**: 「配当学年」が空の科目は、元データ収集時の検索条件（`raw["取得元検索条件"]` = `grade1` 等）から配当学年を復元する（2026年度データでは必修11科目がすべて1年配当であることを確認済み）。全件同期でも学年指定検索でヒットした学年（`ScrapedCourse.sourceGrade`）で同様に補完する。これにより必修の自動配置が対象学年のコマにのみ行われる。
- **基幹科目／総合科目**は科目名の接頭辞から判定できる科目（16件の基幹科目群特論、2件の総合科目群特論）のみタグ付けしており、それ以外の科目がどちらに属するかは学生便覧で確認できていないため空欄のまま。また、この2区分に個別の卒業要件単位数があるのかどうかも未確認のため、卒業判定の単位計算には使用していない（表示・絞り込み専用）。
- **シラバスの実データ**は `public/data/asahikawa-courses-2026.json` として搭載済み（上記参照）。デモ・フェイクデータは廃止済みで、このファイルが唯一のデータソース。`Course.syllabusYear` フィールドで科目データがどの開講年度のものかを保持しており、将来複数年度分のシラバスを取り込む場合に備えているが、2023〜2026年度分を搭載済みで、設定画面の「シラバス年度の選択」から読み込む年度を選べる。
- **シラバス検索フォーム**: `src/lib/scraping/scraper-config.ts` の検索フィールド名（`value(kouginm)` 等のStruts系パラメータ名候補、`<select>` ラベル一致による所属絞り込みなど）はユーザー提供のより詳細な実装パッチを反映したもので、以前の推測実装より実構造に近いと考えられるが、この開発環境からは大学サイト（cx.asahikawa-u.ac.jp）へのネットワークアクセスがゲートウェイでブロックされているため、実際に接続してのフォーム送信確認はできていない（`/api/asahikawa-scrape` はこの環境では常に403で失敗する）。大学サイトへ到達可能な環境で一度実行し、失敗するようであれば `scraper-config.ts` の `fieldCandidates` 先頭に実際のフィールド名を追加すること。調整するまでは、搭載済みの130科目でヒットしない検索語は「見つかりませんでした」と表示され、全件同期（設定画面）も失敗する（いずれもフェイクデータへのフォールバックはしない）。
