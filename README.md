# Jikanwari（時間割PWA）

大学の時間割作成・シラバス検索・卒業要件確認をオフラインでも行えるPWA。旭川大学経済学部経営経済学科を想定した実装。

## 主な機能

- **時間割**: 学年（1〜4年）× 学期（前期/後期/集中）× 曜日・時限の時間割。セルをタップすると、割当済み科目の詳細（教員・単位・評価方法・シラバス・卒業要件区分）や、その時間帯に開講している他の科目の候補一覧（履修登録ウィザード）が表示され、ワンタップで追加・削除できる。「必修を自動配置」で、選択中の学年・学期の必修科目を空きコマへ一括配置できる。
- **履修プランナー**: LLM（AI）は使わず、卒業要件の不足区分・科目データ・時間割の空きコマからルールベースで履修候補を提案。区分（必修/選択必修A〜E/選択/自由選択）ごとに未履修候補を一覧表示し、ワンタップで時間割に追加できる。
- **シラバス検索**: 科目名・教員名・概要・到達目標・評価方法・教科書・キーワードから部分一致・あいまい検索（全角半角統一、カタカナ→ひらがな変換、部分列マッチによるフォールバック対応）。ローカル（IndexedDB）にキャッシュ済みの科目はそこから即座に返し、未キャッシュの検索語のみ `/api/syllabus/search` がサーバー側でスクレイピングを試みる（失敗時は「見つかりませんでした」と表示し、フェイクデータは表示しない）。
- **卒業判定**: 入学年度別（経済学部経営経済学科 2023〜2026年度入学）の卒業要件に対応。必修・選択必修A〜E・選択・自由選択の各区分の取得単位・不足単位・総取得単位を集計し、円グラフ（達成率）・卒業可否・アドバイス（不足区分の候補科目、評価方法の偏りなど）を表示。各科目がどの区分としてカウントされるかは科目名から自動判定（`classifyCourse()`）され、手動指定でも上書きできる。
- **履修状況管理**: 履修済み/履修中/履修予定の3状態管理。履修中の科目も卒業要件の進捗に反映される。
- **PWA**: `manifest.json` + Service Worker（`public/sw.js`）でホーム画面追加・オフライン閲覧に対応。
- **レスポンシブUI**: モバイルは下部タブバー、タブレット/PCは左サイドナビに切り替わる。
- **ローカル保存**: IndexedDB (`src/lib/db.ts`) に `courses` / `timetable` / `graduation`（履修状況） / `favorites` / `settings` を保存。サーバーには送信しない。
- **サーバー側共有キャッシュ**: シラバスのライブスクレイピングに初めて成功した検索語の結果は、Next.jsのData Cache (`unstable_cache`) により外部DB・環境変数なしでサーバー側に30日間共有キャッシュされる。以降は同じ検索語について他の利用者がアクセスしても大学サイトへ再アクセスしない。
- **実データ搭載**: `public/data/asahikawa-courses-2026.json`（2026年度・経済学部経営経済学科130科目、実際のシラバスサイトから取得された科目名・教員・曜日時限・評価方法・概要・到達目標・シラバスURL等）を初回起動時に取得しIndexedDBへ格納する。フェイク／デモデータは一切使用しない。取得に失敗した場合は設定画面にその旨を表示し、次回起動時に再取得を試みる（`src/lib/real-course-import.ts`）。
- **全件同期（学年ベーススクレイピング）**: 設定画面の「大学サイトから最新のシラバスを取得する」から `/api/syllabus/sync` を呼び出し、学年（1〜4年）ごとに検索を行って科目データを再取得・反映できる（`scrapeAllCourses()`）。実データの `raw["取得元検索条件"]` フィールドに `"grade1"`〜`"grade3"` 等の値が残っており、元データもこの学年ベースの検索で収集されたことがわかっているため、同じ戦略を再現している。

## 開発

```bash
npm install
npm run dev
```

`npm run build` でVercelへそのまま `git push` デプロイ可能（環境変数不要）。

## 既知の制限・要調整事項

- **卒業要件データ**（`src/lib/graduation-requirements.ts`）の必修科目名・選択必修A〜Eの分類ルール・単位数は、ユーザー提供の参考実装（学生便覧を参照して作成されたと見られるプロトタイプ）を元にしている。必修科目名11件はすべて実データ（130科目）中に完全一致で存在することを確認済みだが、単位数の要件自体（必修20単位、選択必修各8単位など）は一次情報での最終確認はできていない。本番運用前に学生便覧と突き合わせて修正すること。
- **シラバスの実データ**は `public/data/asahikawa-courses-2026.json` として搭載済み（上記参照）。デモ・フェイクデータは廃止済みで、このファイルが唯一のデータソース。
- **シラバス検索フォーム**: 実データのシラバス詳細URL（`slbssbdr.do?value(risyunen)=...&value(kougicd)=...`）は確認できたが、検索フォーム（`slbssrch.do`）自体のPOSTパラメータ名はこの開発環境から大学サイト（cx.asahikawa-u.ac.jp）へのネットワークアクセスがブロックされていたため確認できていない。`src/lib/scraper.ts` / `src/lib/scraper-config.ts` はApache Struts系の教務システムでよく見られる一般的な構造（GETでCSRFトークン等のhidden fieldを収集→POSTで検索）を想定した汎用実装になっている。実データの `raw["取得元検索条件"]`（`grade1`〜`grade3`, `day1`〜`day5`）から、学年・曜日による絞り込み検索の実在は確認できたが、そのフィールド名（`gradeFieldCandidates` / `dayFieldCandidates`）も他の項目と同様に複数候補を並べた推測実装のままである。大学サイトへ到達可能な環境で実際のフォームのフィールド名・セレクタを確認し、`scraper-config.ts` の値を実構造に合わせて調整すること。調整するまでは、搭載済みの130科目でヒットしない検索語は「見つかりませんでした」と表示され、全件同期（設定画面）も失敗する（いずれもフェイクデータへのフォールバックはしない）。
